---
name: pattern-review
description: Review recurring operational signal sequences against later documented outcomes without future-information leakage.
---

Read configured rules, outcome definitions and the core evaluation output. Use only information available at the stated prediction checkpoint. Compare earlier eligible days, not future outcomes or later corrections.

Report matched-day count, event count, baseline count, missing outcomes and sample limitations. Unknown outcomes are excluded, never treated as negative. Describe associations as exploratory. Do not invent confidence scores or suggest causal attribution from these counts.

Synthetic data demonstrates software behavior only. For real validation, require predefined outcomes, prospective capture, a held-out period and a review of false alarms, missed events and interventions. Propose changes for leader review; do not silently change thresholds to improve a test result.
